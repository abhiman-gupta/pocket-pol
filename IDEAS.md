# Pocket Pol Ideas

**Pocket Pol** is short for **Pocket Polarization**. It is a lightweight, physically based renderer for exploring how polarized light behaves, directly in a desktop or phone browser. The goal is to make the basic concepts accessible through a clear, interactive interface that requires no software installation.

The initial scope follows Pollia's Swift window, Cornell box, and Jarecki material. Its headless command renders the same preset at higher samples per pixel and produces files for downstream tools.

## Current starting point

- The initial prototype under `dist/` uses WebGPU and a CPU fallback. Its startup scene came from PolRay.
- The new browser implementation under `web/` uses Pollia's Cornell geometry and renders in a worker. The headless command shares that renderer.

## Feature ideas

- [x] **Scene selection in the control panel.** Put a Scene selector in the Scene tab and offer Cornell Box as the only preset for now.

- [x] **Fresh renders only.** (Formerly Fresh estimates; the button now reads Fresh render.) Start every render at zero and progressively accumulate the selected samples per pixel. Use one button that reads Fresh render when idle and Stop during rendering. Keep the render statistics hidden while retaining the panel and its data updates.

- [x] **Default Cornell box from PolRay.** Open with PolRay’s open-front room, red and green walls, red sphere, rotated white block, square ceiling light, and square camera framing. Use its RGB diffuse reflectance values in Pocket Pol’s RGB renderer.
- [x] **512 × 512 renders at 64 SPP by default.** The browser renders only at 512 × 512 (previously 256 × 256) and the image size control is gone. The headless renderer accepts 128, 256, and 512 and defaults to 512. Fresh renders default to 64 samples per pixel, and the sample presets are 64, 256, and 1024 (the 8 SPP preset is gone). When the browser falls back to the CPU renderer, it drops to 8 SPP the first time, including a render already in progress. On the M5 in the browser with WebGPU, 64 SPP took about 47 ms at 256 × 256 and 135 ms at 512 × 512; 256 SPP took 125 ms and 466 ms. The CPU renderer takes about 0.3 s per sample at 256 × 256 and 1.1 s at 512 × 512, so 8 SPP takes about 9 s there.
- [x] **Pollia layout and exports.** Recreate the Swift sidebar and viewport, with Scene, Statistics, Display, Camera, and Export. Keep float32 Stokes channels with JSON metadata available through the headless renderer.
- [x] **Jarecki materials.** Use Pollia's Jarecki model for the Cornell box with RGB and monochrome channels and fixed Mueller transport.
- [x] **Headless rendering.** Run the default scene as a batch job at user-selected SPP using the same renderer as the browser.
- [x] **Fast rendering.** Prefer hardware WebGPU for interactive rendering. Support the same shader in headless mode through Dawn and parallel CPU rendering where GPU access is unavailable. Benchmark both speed and agreement with the CPU Stokes channels.
- [ ] **Measure time to accurate Stokes output.** Benchmark GPU tracing, film readback, and time to first visible image separately at 128 × 128 and 256 × 256. Compare randomized low-discrepancy sampling with the current pseudorandom sampler against a high-SPP reference. Measure intensity, Q, U, and V separately and verify on a phone.
- [x] **Benchmarked half precision for Mueller transport on the M5.** Scratch shaders stored the per-path Mueller matrices in `f16` and tested matrix products in both `f32` and `f16`. With the default RGB Cornell box at 256 SPP, the full `f32` shader took 33.7 ms at 128 × 128 and 119.8 ms at 256 × 256. The `f16` products took 32.4 ms and 120.3 ms, respectively. Timings are medians of nine headless WebGPU runs including film readback. Keep `f32` in production. A phone benchmark remains part of the renderer performance work.
- [ ] **Reduce work per GPU estimate.** Keep the progressive display on the GPU and measure the effect of delaying full-film readback until export. On the M5 reference Cornell box at 256 × 256 and 256 SPP, a scratch shader that skipped room-wall shadow tests inside the box took 106.2 ms versus 111.9 ms for the current shader and produced identical output. Sharing geometric calculations across RGB took 108.9 ms.
- [x] **Orbit the scene camera like Pollia.** Drag the viewport to orbit the Cornell box and render the new camera angle on release. Arrow keys also orbit the camera. Keep camera distance as the only slider and use the default camera position for browser PNG exports.
- [x] **Live camera preview while dragging.** Render a quick low-resolution preview during the drag (now quarter resolution, 4 samples, smoothly scaled). Use the selected resolution and sample count on release. Keep the temporary previews out of the film and exports.
- [x] **Live light updates.** While a light slider (degree of polarization, angle of polarization, ellipticity) moves, show one-sample, reduced-resolution previews like camera orbiting, then start a full fresh render on release. Switching between Unpolarized and Polarized renders immediately. Re-render remains for other scene settings.
- [x] **Channel selector on the image.** A compact RGB / R / G / B switch in the image's top-right corner picks what the image shows, live, without re-rendering. The browser always renders RGB, so the Mono/RGB scene setting and the Display channel menu are gone (the headless renderer still offers mono). RGB shows RGB Intensity and RGB Analyzer in color, and the scalar filters (DoP, AoLP, Q/I, …) use luminance-weighted Stokes parameters. R, G, or B shows only that channel. (Refined below: RGB now offers only the RGB filters.)
- [x] **Render on every release.** Every scene change starts a fresh render as soon as it is let go: light sliders, camera distance, orbiting, arrow keys, max depth, and the sample count. The camera distance slider previews live while it moves, like the light sliders. The Fresh render and Re-render buttons are gone; a Stop link appears in the Render card only while rendering. Display zoom is gone.
- [x] **Log scale suggestion for DoP.** The Filter card shows a Log scale switch for Intensity, Analyzer, and Degree of Polarization. When most of the image has a low DoP, it suggests turning log scale on so the small values become visible (when 75% of sampled pixels are under 25% DoP; the default Cornell box is mostly under 6%).
- [x] **Max depth stepper.** Max depth uses − and + buttons instead of a number field with arrows, as in Pollia, and each change re-renders.
- [x] **Drag to orbit overlay.** On page load, four arrows (up, down, left, right) and “Drag to orbit” sit over the image and fade away at the first drag, key press, or after a few seconds. The hints wait until the first image replaces the “Rendering…” message (noticeable on the slower CPU renderer), and their timer starts then.
- [x] **Export window for high-SPP renders.** An Export button under the image opens a dedicated export window. People choose a higher sample count (1024, 4096, 16384, or a custom value), see an estimated time, and watch the render progress in its own worker while the main viewer stays available. The export window is an in-page dialog (full screen on phones), and closing it keeps the render going with a progress badge on the Export button. When it finishes (or is stopped), they download a PNG of the current filter and channel, or the float32 Stokes channels with JSON metadata as a zip, following Pollia's Save Image and Save Channels.
- [x] **Simpler sidebar, round two.** Exposure is gone for now, and with it the Display tab; color map, colorbar, and range move into an Image adjustments section inside the filter card. The filter card is renamed Image Filters (earlier Display Filters) and sits after Light Source (it briefly came first). The Render card becomes the Render Settings tab, last after Scene and Camera. The Live tags and the grey SPP counter in the Render card are gone.
- [x] **Scene name under the credit.** Below “Created by Abhiman Gupta”, show the current scene's name (Cornell Box for now; a d’Alembert statue and custom uploads later).
- [x] **Filters follow the channel switch.** Display Filter lists every filter in any channel view. Picking a single-channel filter (Intensity, Analyzer, DoP, AoLP, ellipticity, Stokes) while RGB is selected moves the channel switch to G; picking RGB Intensity or RGB Analyzer while R, G, or B is selected moves it to RGB. Changing the channel switch itself maps Intensity ↔ RGB Intensity and Analyzer ↔ RGB Analyzer (other single-channel filters go to RGB Intensity) and restores the previous filter when switching straight back.
- [x] **Analyzer angle from −90° to +90°.** The analyzer slider is centered at 0° for both RGB Analyzer and Analyzer.
- [x] **Toggle color channels hint.** Like the Drag to orbit overlay, an arrow points at the channel switch on load with “Toggle color channels” and fades at the first interaction.
- [x] **Decade ticks on log colorbars.** Log scale colorbars put ticks at powers of ten (10⁻³, 10⁻², 10⁻¹, 10⁰ by default). Colorbars no longer say “Luminance”.
- [x] **Stokes names.** Q / I, U / I, and V / I are now called Q-Stokes, U-Stokes, and V-Stokes.
- [x] **Camera distance under the image.** The Camera tab is gone. The camera distance slider sits right under Export and Reset camera so people find it and zoom in on the polarization patterns; the tabs are now Scene and Render Settings.
- [x] **Image Adjustments card.** Color map, Show colorbar, and Range move out of the filter card into their own Image Adjustments card (now last in the sidebar), shown for filters with a colorbar. Log scale stays in Display Filters.
- [x] **Shorter subtitle and scene title.** The page subtitle, meta description, README, and GitHub description drop “No downloads. No command line.” and reads “A physically based polarization renderer that runs entirely in your browser.” The scene line reads “Scene: Cornell Box”. It sits centered directly above the image (centered on the image itself, not the colorbar column), which frees header space. On desktop the sidebar starts level with the top edge of the image, below the scene name.
- [x] **Default render as the icon and link preview.** The browser tab icon, Apple touch icon, and the Open Graph/Twitter image shown when the link is shared (iMessage, Slack, social) use a high-sample render of the default Cornell box (1024 SPP from the headless renderer: `web/preview.png`, with 180, 64, and 32 px icons). Later, switch the icon and sharing card to a d’Alembert statue render once that scene exists.
- [x] **Everything above the fold on desktop.** On first load on a desktop screen, the image, Export, Reset camera, and the camera distance slider all fit in the window without scrolling (checked from 1000 × 600 to 1920 × 1080). Short desktop windows get a tighter header, and on small images (phones) the Toggle color channels hint stays on one line in a smaller font beside the switch, above the ceiling light.
- [x] **Max path depth.** The Scene tab's Max depth control is labeled Max path depth.
- [x] **(?) help instead of inline explanations.** A circled question mark at the right of the Light Source and Display Filters headings opens a dialog box of definitions (unpolarized light, degree of polarization, angle of polarization, ellipticity; and every display filter). The dialog scrolls on its own and fits phone screens; Escape, the close button, or a click on the backdrop closes it. The inline filter explanations and the ellipticity scale line are gone.
- [x] **Light source sliders only.** The Unpolarized/Polarized menu is gone; the three sliders are always shown and DoP starts at 0% (unpolarized).
- [x] **Channel switch in Image Filters.** The filter card, now called Image Filters, has its own RGB | R | G | B switch above the filter menu, kept in sync with the one on the image, so the menu shows plain filter names (an earlier version appended “(Green Channel)” to each). Colorbar titles still name the channel, for example “Q-Stokes (Green Channel)”.
- [x] **Max path depth help and Image Adjustments last.** Max path depth has its own (?) dialog explaining bounces, what low and high depths show, and suggesting stepping from 1 to 6 with DoP or Q-Stokes selected, so people experiment with it. The Image Adjustments card moves to the end of the sidebar as “Image Adjustments (Advanced)”, below the Scene and Render Settings tabs.
- [x] **Less space above the title; analyzer wording.** The page's top padding drops to 12–24 px so everything sits higher and the render gets that space. The Analyzer and RGB Analyzer explanations say “Light intensity passed by a linear polarizer…”.
- [x] **One Render Settings card.** The Scene and Render Settings tabs are gone. A single Render Settings card holds Max path depth (with its (?) help) and samples per pixel. The Scene menu is removed while Cornell Box is the only scene; bring a scene picker back when the d’Alembert statue and uploads arrive. The credit follows the tagline after a plain space, without the “·”.
- [x] **Smooth drag previews and decorrelated sampling.** Drag and slider previews showed parallel diagonal streaks: each pixel's random seed was the frame seed XORed with linear functions of the pixel and sample index, so neighboring pixels' LCG streams were correlated. Both the WebGPU shader and the CPU tracer now seed through a PCG hash (identical in both, so they still agree), which removes the streaks at any sample count. Previews also render at quarter resolution with 4 samples (the same cost as half resolution with 1) and are scaled smoothly with a slight blur instead of pixelated blocks.
- [ ] **Desktop and phone support.** Verify that users can open, edit, and render a scene on both desktop and phone browsers. Tune preview quality so the controls stay responsive during rendering.

- [ ] **Polarization learning tool.** Grow Pocket Pol into a tool for learning polarization, not just a renderer, building on the interactive light and analyzer controls.

## Future scene and material tools

- [ ] **Bring your own 3D model.** Let users load a 3D file from their device, place it in the scene, and render it under a light source. Supported formats and import settings are open decisions. Planned UI: an “Upload 3D” button to the right of Export under the image creates a new scene from the uploaded object, and the “Scene: Cornell Box” title becomes “Scene: [dropdown]” so people can switch between Cornell Box, the d’Alembert statue, and their uploads.
- [ ] **PBR and polarized ray tracing (PRT).** Let users render the same model and lighting in either mode so they can compare an ordinary physically based image with a polarization-aware render.
- [ ] **Quick glass and isotropic crystal presets.** Make it easy to render a glass statue or a simple isotropic crystal for fun. Use Schlick’s approximation for angle-dependent Fresnel reflectance in the quick PBR preset. Use polarization-aware Fresnel transport for a polarized dielectric preset.

- [ ] **D’Alembert statue scene.** Add a built-in scene featuring a statue of d’Alembert.

The initial browser version follows the features in Pollia's window.

Defer Jones transport. Use Stokes vectors and Mueller matrices for path accumulation in both the browser and headless renderer.
